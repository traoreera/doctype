This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

**Product vs samples (decision of 19 Oct 2026).** Apart from xauth (`app/auth`), its DocType face `iam` and the base settings plugin `system`, the plugins in `app/` (`sales`, `stock`, `hr`) are **test fixtures for the DocType engine**, not products: do not build business features on them, extend the engine and the Desk instead.

`xcore-doctype` is an **xcore plugin** that will bring a Frappe-inspired DocType engine (one declarative YAML/JSON definition → storage, CRUD API, permissions, hooks, Vue UI). Scope is deliberately "20 % of Frappe".

Phases 0 to 4 (the "20 %" tier) and **phase A of the "40 %" tier** are done (results: `doc/spike-phase0.md`, `doc/phase1.md`, `doc/phase2.md`, `doc/phase3.md`, `doc/phase4.md`, `doc/phase-a.md`, in French; the 40 % contract and its roadmap A-F are `doc/palier40.md`). Implemented: definition schema, generic JSON-table storage, tenant-scoped CRUD over HTTP and xcore actions, optimistic locking, convention-based grant permissions with row-level `if_owner` (`match` frozen), hooks (`validate`, `before_save`, `after_save`, and sandboxed `action:` hooks), `depends_on` / `mandatory_depends_on` / `read_only_depends_on` (written as strings, compiled server-side to a JSON AST), typed list filters, search, the **Desk** (Vue 3 + PrimeVue SPA in `ui/`, served by the plugin), and the phase-3 "rich documents": complete Link checks, child tables (`Table` fields, `istable` DocTypes), series numbering (`naming: {series: ...}`) and change history (`/history`), plus the delivery layer: `xcore-doctype` CLI, wheel shipping the Desk, `doctype_registry` service for business plugins, opt-in PostgreSQL RLS, GitHub Actions CI (written, never run). Scope was then raised to "70 % of Frappe" (`doc/palier70.md`: a countable inventory; phase G, the workspace-style Desk, is done: `doc/phase-g.md`). The Desk was reviewed (`doc/desk-revue.md`): responsive layout with an off-canvas menu, dark mode, session renewal against xauth, readable lists (document number column, right-aligned numbers, units), a home page with recents, conditions inside child rows, `today` date defaults and `unit_from`. Phase A added **submittable documents** (`docstatus` draft → submitted → cancelled, `submit`/`cancel`/`amend`, `on_submit`/`on_cancel` hooks that write other documents in the same transaction), the exact **`Decimal`** field type, and the **`stock` plugin** (`app/stock`: quantities only, movements that post to an immutable ledger, balances maintained and verifiable, negative stock refused under concurrency on SQLite and PostgreSQL). **Not implemented yet:** dedicated tables and migrations (phase B: the stock ledger still lives in the generic JSON table), saved views / reports / CSV export (C), workflows, comments, attachments (D), import, Single/tree DocTypes, global search, jobs, webhooks (E), printing and field-level permissions (F), hooks on delete, conditions inside child rows, nested tables, history retention/purge, link rules between DocTypes' states (a Link to a cancelled document is not refused), MFA in the Desk, drag-and-drop row ordering, configurable list columns and saved filters (phase C).

Read these before changing design-level behaviour:
- `doc/doctype.md`: the design contract (v3, **French**). Decisions are numbered D1–D22 and referenced from code comments.
- `doc/spike-phase0.md`, `doc/phase1.md`, `doc/phase2.md`, `doc/phase3.md`, `doc/phase4.md`: what each phase confirmed, the decisions taken, and the deviations from doctype.md (they win where they differ).

## Commands

Python `>=3.14` (Poetry), Node + pnpm 11 for the Desk (developed on Node 26). Everything goes through `makefile` (`make help` lists it):

```bash
make install        # poetry install + pnpm install --frozen-lockfile (ui/)
make dev            # backend :8000 AND Vite :5173 together, both reload; Ctrl-C stops both
make token          # logs in to xauth as the .env administrator and prints an access token (FIELD=tenant_id: the organisation id); the server must run
make member EMAIL=bob@example.com PASSWORD='Bob-Passw0rd!1'   # a second dev user in the administrator's organisation (register, invite, accept, grants)
make serve          # builds the Desk, then serves it FROM the backend at /app/xcore-doctype/desk/ (no reload): the delivered setup
make check          # build-ui (vue-tsc + vite) + all Python tests (e2e + delivery included) + vitest: run before handing work over
make install-check  # the wheel in a clean venv + a fresh `xcli init` instance (tests/delivery): the delivery criterion
```

- `make dev` = `dev-backend` (`uvicorn main:app --reload`, reloading on Python **and** `*.yaml` changes under `src/` and `app/`, so on DocType edits) + `dev-frontend` (Vite; its proxy sends `/app` to the backend, and a dev middleware answers `/config.json` like the plugin does). Open `http://localhost:5173` and log in with `ADMIN_EMAIL` / `ADMIN_PASSWORD` from `.env` (the Vite dev middleware sets `login_url` to xauth's `/app/auth/login`).
- **Authentication is xauth, in this repo (`app/auth`, `doc/xauth.md`).** `make env` (run by `make dev`/`serve`) writes the git-ignored `.env` (`ADMIN_EMAIL=admin@example.com`, a random `ADMIN_PASSWORD`) and the JWT keys `conf/private.pem` / `conf/public.pem`; xauth creates that administrator and the `default` organisation at first start (**xauth refuses to load without `ADMIN_EMAIL`/`ADMIN_PASSWORD`, there is no default password**). The backend binds `127.0.0.1` (`HOST=` to change it: the administrator account becomes reachable from the network). `PORT=`, `UI_PORT=` are overridable. The manifest's own `env:` block of `app/auth/plugin.yaml` carries only the `${ADMIN_EMAIL}`/`${ADMIN_PASSWORD}` indirection (no cleartext, no default): xcore resolves it from the environment (the `.env` loaded by `app.dotenv`), so `make env` and `make dev`/`serve` export those names and nothing secret is committed. The dev database `xcore.db` holds xauth's tables beside the engine's: delete it to start over.
- `xcore-doctype check app/sales/doctypes --owner sales --with app/stock/doctypes` validates a plugin's DocTypes; `--with` names the DocType folders of the plugins it `requires` (their DocTypes are the targets of its Link fields, not checked themselves).
- Tests: `make test` (all Python, SQLite, e2e included), `make test-unit` (fast), `make test-pg PG_URL='postgresql+asyncpg://user@host:port/db'` (adds PostgreSQL: start a throwaway `initdb` + `pg_ctl` on 127.0.0.1 yourself, the URL needs the `asyncpg` driver from the `dev` group), `make test-ui` (vitest), `make typecheck-ui`, `make e2e` (rebuilds the Desk, then real Chromium against a real uvicorn host with a fresh DB and tenant; skipped with a reason if node/pnpm install/build/Chromium is missing; `E2E_DEBUG=1 make e2e` also prints every HTTP error response with its body, the first thing to look at when a step fails; `E2E_TIMEOUT=8000` shortens Playwright's 30 s waits so failures surface fast). One test: `poetry run pytest tests/unit/test_query_leak.py -k delete`. `make expr-vectors` regenerates `tests/vectors/expr_asts.json`.
- **`pyproject.toml` must stay valid for Poetry** (`poetry check`; CI runs it): an `authors` entry needs `name` and/or `email` (a `{homepage = …}` entry breaks `poetry run`, `install` and `build`, hence every `make` target; the homepage belongs in `[project.urls]`).

The old targets copied from the xcore repo (`lint-*`, `security`, `ci-*`, `scanner-core`, `init`, `pre-commit*`, `benchmark`) are gone: they pointed at an `xcore/` directory and `./script/*.sh` that do not exist here. No linter or formatter is configured for this project.

## Architecture

Request path: HTTP route (`api/http.py`) or xcore `@action` (`plugin.py`) → builds an immutable `RequestContext` (`context.py`) → `DocumentService` (`document.py`, the only door to data; orchestrates permissions and hooks) → `Query(session, ctx, tables)` (`query.py`, the only place SQL is built) → generic table `xdt_document` (`db/tables.py`).

Rules that span files:

- **Definition-driven.** `schema.py` (Pydantic, `extra="forbid"`) → `builder.py` (a `create_model` write validator per DocType) → `registry.py`. No per-DocType code. The schema **rejects** blocks the engine doesn't enforce yet (today: series naming, only `naming: hash` is accepted) instead of ignoring them; allow a block only in the commit that implements it.
- **Permissions deny by default** (`permissions.py`). xauth already resolves roles and grants per request, so a DocType does **not** restate an RBAC matrix: with no `permissions` block, grants come from `module` + the DocType name (`schema.conventional_grant`): `read` → `<module>:<doctype>:read`, `write` **and** `create` → `…:write` (xauth's "Créer/modifier"), `delete` → `…:delete`. An explicit `permissions: {read: [...], write: [...], create: [...], delete: [...]}` replaces the convention **per action** (an entry is a grant string, or `{grant, if_owner, description, tenant_grantable}`; `[]` closes the action for everybody). Grants are checked against `principal["permissions"]`; **role names never count** (free text per tenant in xauth; `role:x` is rejected with an explanation). A `Scope` per (user, action) is compiled once and has two interpreters that must stay equivalent: SQL in `Query` (reads/updates/deletes, never filtered after the fact) and Python `Scope.allows` for the *written* value; `tests/unit/test_permissions_matrix.py` checks both against an independent in-memory oracle. No action granted → 403; document outside the READ scope → 404 (indistinguishable from missing); update/delete require read access. `match` is **frozen** (`schema.MATCH_ENABLED = False`: xauth's `user` carries no attributes); code and tests stay, tests flip the flag with `monkeypatch`; its planned replacement is an auth scope (`doc/phase1.md` §7). `Query` takes a **required** `scope`; the system context uses `Scope.everything`. `module` is the grants' namespace: `[a-z0-9_]+`, not one of xauth's reserved namespaces.
- **Grants have one source: the DocType YAML.** `GrantCatalog` (`grants.py`, exported as the service `doctype_grants`) lists the grants the DocTypes need in `rbac.declare` format; the **owning plugin** (named like the `module`) passes `for_plugin(self.ctx.name)` to a **single** `rbac.declare` (xauth deactivates a plugin's grants missing from the list it receives). xcore-doctype never emits `rbac.declare` itself.
- **Hooks** (`hooks.py`, orchestrated in `document.py`). Trusted hooks are coroutines registered by name in a per-instance `HookRegistry`, exported to other plugins as the service `doctype_hooks`; hook names are registry keys, never imported paths (D16). Save order: permission → hook availability → schema + written-value check → `action:` hooks (sandboxed plugins, **outside** any transaction, tenant/principal passed explicitly, output revalidated like client input) → transaction with trusted `validate` then `before_save` → commit → `after_save` + EventBus event without document content. A hook referenced but not registered **refuses the save** (503), never skipped. `validate`/`before_save` are called directly because `EventBus.emit` swallows errors. Never log with a field named `msg` (xcore's logger is `error(msg, **fields)`).
- **Conditions (`expr.py`, D22).** `depends_on`, `mandatory_depends_on`, `read_only_depends_on` are strings in the YAML, parsed by the ONE parser in `expr.py` (no `eval`) into a whitelisted JSON AST that `/meta` sends and `ui/src/lib/expr.ts` evaluates; the server re-evaluates the same AST on write (`builder._condition_errors`). Same type-strict semantics in both languages (`1 == true` is false, strings compare by code point, `0`/`""` falsy): change one side and the shared vectors fail. A field with `depends_on` is required only when visible; `read_only_depends_on` is evaluated on the **stored** document and only for client input (hook output is exempt), so the Desk evaluates it on the saved values for an existing document.
- **Filters are typed per field** (`FILTER_OPS`): no ordering on Text/Select/Link (collation differs per backend), `like` is case-insensitive with escaped wildcards, `in` ≤ 100, `!=` also matches NULL, `name` is filterable as Text. `GET /search/{doctype}` feeds Link autocompletion; the Desk resolves Link titles with a `name in [...]` list call.
- **The Desk is served by a separate PUBLIC router** (`api/desk.py`, `<plugin_prefix>/xcore-doctype/desk/`) mounted beside the protected API router: static files only (path traversal and symlink escapes refused, strict CSP, `assets/` immutable), plus `config.json` (API base derived from the request URL, optional `login_url`: the sentinel `auth` means `<prefix>/auth/login`, derived from the request prefix so it follows `plugin_prefix`). The SPA holds its token in `sessionStorage`, talks through a replaceable `Transport` (`ui/src/lib/transport.ts`, for a future Tauri port), uses hash routing and sends `X-Tenant-ID` read from the token claims (D17).
- **Series numbering (`naming.py`, D7/D13).** `naming: {series: "FA-{YYYY}-{#####}"}` → `FA-2026-00001`. The counter row is `(tenant_id, doctype, resolved series)` and is incremented by ONE `INSERT … ON CONFLICT DO UPDATE … RETURNING` (`Query.next_number`) **inside the document's transaction, as the last step before the insert**: no gap when anything fails, no duplicate under concurrency (mutation-checked on SQLite and PostgreSQL), at the price of serialising creations of one series until commit. Consequences: hooks see `event.name is None` on a series DocType's creation; numbers are never reused after a delete. Date parts use `doctype.timezone` (default UTC).
- **Links are checked, not just typed.** On write, every *changed* Link value (top-level or inside a table row, path `items.0.item`) must exist in the tenant AND be readable by the caller; unreadable looks exactly like missing (`link_not_found` 422). On delete, `DocumentInUse` (409 `document_in_use`) when any document or table row of the tenant still cites it (references are looked up WITHOUT the caller's scope; the answer names DocTypes and fields, never documents). Integrity has no foreign keys: PostgreSQL row locks do the work (`FOR KEY SHARE` while linking, `FOR UPDATE` before the reference scan on delete; `tests/unit/test_links.py::TestRace` pauses transactions to prove it); SQLite has no row locks, so a narrow window between check and delete remains (documented, those tests skip on SQLite). `registry.validate_links()` makes an unknown Link target a load error.
- **Child tables.** A `Table` field's `options` names an `istable: true` DocType; its rows are a JSON array inside the parent (≤ 500 rows, empty list ≡ absent, validated per row with the child's strict model, errors addressed `items.0.qty`). A child has no routes, rights, hooks, module, layout, title, series, nested tables or conditions (all refused at load) and answers 404 `doctype_not_found` like an unknown DocType. The registry loads children first (`load_dir` sorts them; `register` requires them registered before the parent). Tables cannot be filtered, sorted or used in conditions. `/meta` embeds the child fields under `children`.
- **History (`versions.py`).** `xdt_version` rows (`track_changes`, default true) are written in the SAME transaction as the document: `create` = diff against nothing, `update` = changed fields only (a no-op update writes nothing), `delete` keeps the deleted content and owner. `GET /history/{doctype}/{name}` needs read access to the document; for a deleted one it judges the read scope on the stored snapshot. No retention policy yet.
- **Business plugins bring their own DocTypes** (`registry.DocTypeChannel`, service `doctype_registry`): `load_dir(self.ctx.name, dir)` in `on_load`, `unregister_owner(self.ctx.name)` in `on_unload`. Every DocType's `module` must equal the plugin name (children, which have no `module`, belong to the plugin that brings them), so a plugin cannot write into another's grant namespace; a plugin name that is not `[a-z0-9_]+` owns nothing. Loading is all-or-nothing and validates Link targets of the newcomer only (so Link targets must come from the plugin itself or one it `requires`). Ownership is by the name the plugin passes (like `doctype_hooks`): it prevents mistakes, not a hostile trusted plugin. `doctypes_dirs` stays for the operator's own DocTypes (free `module`); the shipped manifest sets none. The `rbac.declare` source-forcing fix (xcore + xauth) is still deferred.
- **Submittable documents (`submittable: true`, `document.py`, phase A).** `docstatus` is a real column of `xdt_document` (0 draft, 1 submitted, 2 cancelled; `amended_from` beside it), never a key of `data` (a payload cannot set it). `POST /doc/{dt}/{name}/submit|cancel` (body `{version}`) and `POST …/amend`, mirrored by the actions `doc.submit|cancel|amend`. Two more permission actions, `submit` and `cancel` (grants `<module>:<doctype>:submit|cancel`), exist ONLY for a submittable DocType (declared to auth only then; `write` never implies them; amending needs `create` + `read`). A submitted or cancelled document is **frozen**: `Query.update`/`delete` carry `docstatus = 0` in their WHERE (409 `document_locked`), only a draft is deleted. A transition is one conditional `UPDATE … WHERE version=? AND docstatus=?` (`Query.transition`), executed FIRST in the transaction: a replayed or simultaneous submit passes once (409 `invalid_docstatus` for the others, hooks run once) and on SQLite that write is what takes the database lock before any hook reads (`test_submit.py` mutation-checks it). Then the history entry (`submit`/`cancel`, diff of `docstatus`), then the hooks, then the EventBus event `doctype.<name>.after_submit|after_cancel` (no content). `submit` re-validates the stored draft against the CURRENT definition. `amend` copies a cancelled document into a draft named `<name>-1` (the next suffix for an amendment of an amendment); a document is amended once (`already_amended`, the unique name enforces it under concurrency). A submittable DocType must keep `track_changes` (who submitted/cancelled is the point). `docstatus` is filterable (`{"docstatus": 1}`, `["in", [0,1]]`) and sortable. Existing databases gain the two columns at startup (`db/access._add_missing_columns`: additive only, nullable or with a default).
- **Transition hooks (`on_submit`, `on_cancel`) and `HookEvent.tx`.** Trusted only (an `action:` hook cannot join a transaction), they run INSIDE the transaction of the transition, so a refusal (`DocumentValidationError`) undoes the state AND everything the hook wrote. `event.tx` (`hooks.HookTransaction`, implemented by `document._Transaction`) is the ONLY way a hook writes: `get(doctype, name, lock=)`, `create(…, name=)`, `ensure(…)` (atomic create-if-absent, `ON CONFLICT DO NOTHING`), `update(…, version)`, `today` (organisation timezone). No permission is checked (trusted code) and links are checked on existence only, but every write is validated like any other (strict types, links, numbering), historized under the submitting user, and refused (`hook_not_supported`) for a DocType that declares hooks of its own, which would not run. Invalid data from a hook is a hook defect (500 `hook_invalid_write`), not a 422. A hook that reads then writes MUST lock (`tx.get(..., lock=True)`: `FOR UPDATE` on PostgreSQL; SQLite has no row lock and relies on the state write being first) and should take several locks in a fixed order (deadlocks).
- **`Decimal` fields (`decimals.py`).** Stored as a canonical STRING with exactly `decimals` digits (`"12.500"`, `decimals` mandatory 0-9), never a JSON number: a float is refused (`0.1 + 0.2`), as is any value needing more decimals (no silent rounding), more than 18 digits, an exponent, `+`, NaN. Code that computes uses `decimal.Decimal(value)`; `canonical()` also accepts a `Decimal`. Filters/sorts cast to `NUMERIC` (`as_numeric`; SQLite compares as doubles, exact to ~15 digits). A Decimal cannot appear in a condition. The Desk keeps it a string end to end (`ui/src/lib/decimal.ts`, same vectors: `tests/vectors/decimal_cases.json`); the comma of a French keyboard is normalised, list filters on a Decimal separate with `;`.
- **Conditions inside child rows (`schema.PARENT_PREFIX`, `builder.CompiledDocType.row_conditions`).** A child field may carry `depends_on` / `mandatory_depends_on` (not `read_only_depends_on`: a row has no identity to compare). They read the row's own fields AND the parent's through `parent_<field>` (`parent_purpose != 'Réception'`); `parent_` is reserved in child field names. Compiled per PARENT (`CompiledDocType.compile`, the same child may serve another parent), parent names are checked at registration (`InvalidDefinition`), a parent Decimal/Table cannot be read, `/meta` sends the trees (never strings) under `children`. The server re-evaluates them on write (`_row_errors`: a cell made mandatory cannot be missing, error path `items.0.source_warehouse`); a hidden value is kept, not stripped (a hook refuses what the business forbids), but the Desk does not SEND values of cells the condition rules out. The Desk hides a column nobody can fill (`TableField`), and evaluates with an empty row when there is none.
- **Dates and units in definitions.** `default: today` on a Date field (not in rows) is resolved at creation in the organisation timezone (`DocumentService._with_today`, also for `tx.create`); `/meta` keeps the marker and sends `timezone`, the Desk resolves it with `Intl` (`lib/format.todayIn`), never with the browser's own day. `unit_from: uom` or `unit_from: item.uom` on a Number/Decimal field is DISPLAY only (checked at load: `registry._check_units`); the Desk reads the linked documents in one request (`stores/links.resolve(…, { data: true })`, in-flight lookups are shared). `/meta` summaries carry `create` (the home page offers "+" only there).
- **The `stock` plugin (`app/stock`, quantities only).** Owns `Item`, `Warehouse`, `Stock Entry` (+ `Stock Entry Line`), `Stock Ledger Entry` and `Bin`; `sales` `requires` it (its invoice lines cite `Item`). Rules live in `app/stock/src/ledger.py`. Submitting a Stock Entry (`purpose` Réception/Sortie/Transfert) writes one ledger line per entry/exit (named `<voucher>.<line>.in|out`, `.rev` for a cancellation: a unique name makes double posting impossible), maintains the `Bin` balance and REFUSES negative stock; cancelling writes the inverse lines (the ledger is never edited or deleted). Ledger and Bin are closed to every human writer (`permissions: {write: [], create: [], delete: []}`), written by the hooks only. Bins are created with `tx.ensure` and locked in sorted order. **No backdating** (decision 2 of `doc/palier40.md` §8): a movement may not be dated in the future nor before the last movement on any of its (item, warehouse) pairs; a cancellation is dated today and never refused for its date. No valuation (decision 1). `balances.verify` (IPC action, operator: `{"tenant": …}`) recomputes balances from the ledger through the read-only service `doctype_documents` (`SystemReaders`, system context named by its reason) and reports drift without fixing it. The ledger lives in the generic JSON table until phase B (dedicated table).
- **RLS is opt-in** (`doctype.rls: true`, PostgreSQL only, `db/rls.py`): `FORCE ROW LEVEL SECURITY` + policy on the three `xdt_*` tables, tenant set by `set_config('xdt.tenant_id', …, true)` (transaction-local) in `DocumentService._query` before anything else. `ensure_rls` REFUSES to start for a non-PostgreSQL database, a superuser/`BYPASSRLS` connection role (policies would not apply) or a role that does not own the tables. Tests need a real ordinary role: fixture `rls_app_url` (tests/conftest.py) creates one; the throwaway superuser database proves nothing about RLS.
- **Delivery**: xcore only discovers plugin FOLDERS, so `pip install` alone loads nothing. `xcore-doctype install ./app` writes `app/xcore-doctype/{plugin.yaml, src/main.py}` (shim rewritten every time; the manifest is the operator's copy, kept unless `--force`; `enforce_tenant_binding` follows the host's tenancy) and reports what a fresh `xcli init` instance gets wrong (sync SQLite adapter, no `xcore.setup(app)`). The `xcore.plugins` entry point declared in pyproject is inert until xcore reads it (`doc/xcore-issues.md` holds the drafted requests; nothing in xcore was modified). `src/xcore_doctype/ui/dist` must be in pyproject `include`: `.gitignore` drops `dist/` and, measured in a git checkout, the wheel has 0 Desk files without it, 24 with.
- **Desk shell (phase "revue").** Below 900 px the sidebar is an off-canvas drawer (`AppShell`: closes on navigation, Esc, backdrop) and a row of a child table reads as a card (`td[data-label]`); numeric list columns are right-aligned; a numbered DocType (`naming: {series}`) shows its number as the first list column. Dark mode = class `app-dark` on `<html>` (`stores/theme.ts`, choice kept in localStorage, `system` follows the OS live); PrimeVue tokens are semantic (`{content.background}`…) and every non-token colour goes through `--desk-*` / `--pill-*` variables defined per scheme in `desk.css`: never write a colour in a component. Session: with xauth the login body carries `refresh_token`; `stores/session.ts` renews one minute before expiry (single-flight: the token rotates and is single-use), on a 401 `ApiClient` renews once and retries the request once, a refused renewal ends the session, a network failure retries in 30 s, `logout` revokes server-side; the refresh/logout URLs derive from `login_url` (`…/login` → `…/refresh`), no second setting. A dev token cannot renew: the Desk warns two minutes before it expires. Only one toast stays on screen. The home page keeps the last 8 documents per tenant+user in localStorage.
- **Workspaces (`workspaces.py`, phase G of `doc/palier70.md`).** A plugin describes its module's home page in `<plugin>/workspaces/*.yaml` (`name` = the plugin = the module, `label`, `icon`, `description`, `order`, `blocks`: a CLOSED list of `header` / `shortcut {doctype, label?, new}`; nothing executable; charts and number cards will be new block types), loaded by `doctype_registry.load_workspaces(self.ctx.name, dir)` AFTER `load_dir` (shortcuts must hit loaded, non-child DocTypes; all-or-nothing; removed with the plugin). `GET /workspaces` / action `meta.workspaces` return them FILTERED by the caller's rights (unreadable shortcut gone, header with no visible shortcut gone, empty workspace gone, `create` only for who may create); a module with no file gets a made one. `icon` on a DocType is a bare PrimeIcons name (`receipt`). The Desk's sidebar lists WORKSPACES (expand = their types, state kept per device in `lib/navstate.ts`), `Ctrl+G` / `Ctrl+K` open the command palette (`lib/commands.ts`: types, workspaces, recents, "Nouveau", theme, logout; it does NOT search documents), a workspace page shows shortcuts with document counts (one `limit=1` list call each).
- **Views, dashboards, aggregates (`aggregation.py`, `dashboards.py`, `doc/phase-ij.md`).** `Query.aggregate` (the only SQL; count/sum/avg/min/max, group by Select/Link/Boolean/Date+bucket or `docstatus|owner|creation|modified`, `periods` window with empty periods filled) behind `GET /aggregate/{doctype}` and action `doc.aggregate`; same typed filters and read scope as the list. Workspaces accept blocks `header|paragraph|spacer|shortcut|number_card|chart|quick_list|card`; a DocType declares `views: {kanban, calendar, gantt, dashboard, default}` (list, report and a GENERATED dashboard always exist; `/meta` sends `views`). Block mistakes are LOAD errors (`dashboards.check_measured`), blocks are filtered by the caller's rights, a module without workspace file gets a generated dashboard. A `required` field gets no server default (an API create must send it): give Kanban fields a `default`, not `required`. Desk: `ListView` hosts the six views with filters shared across them (`?view=`, `?filters=`), charts are hand-made SVG (`ChartSvg.vue`, palette `--chart-1..8` validated with the dataviz skill; never a 9th hue, fold into « Autres »), CSV export neutralises formula cells. `ui/e2e/look.mjs` seeds a demo tenant and takes screenshots.
- **Field types, files, single documents, HR (`fieldtypes.py`, `files.py`, `file_service.py`, `doc/phase-h.md`).** `Datetime` (UTC, fixed-width ISO, default `now`), `Currency` (= Decimal; `schema.DECIMAL_TYPES` covers both, branch on it, never on `"Decimal"` alone), `Rating`, `Color`, `LongText`, `format:` on Text. `Image`/`Attach` fields hold a 32-hex file id; blobs live in `ext.storage` (orchestra-backend's storage extension) or a local dir; metadata in `xdt_file`; files are served ONLY through short HMAC-signed URLs on a public route (`api/files.py`), read rights = right to read a document citing the file; images are sniffed by content, SVG refused, attachments never inline. `single: true` DocTypes are opened virtually at `version: 0` and created by `update(version=0)`. `app/hr` is a YAML-only plugin (a few-line `main.py`): the template for a new business module. `CellValue.vue` renders every value (clickable links, mailto/tel/https, swatch, stars, thumbnails): use it, do not format cells by hand.
- **Personnaliser (`BlockEditor.vue`, `lib/blocksedit.ts`, `overrides.py`, `doc/phase-h.md`).** Un espace ET le tableau de bord d'un type s'éditent sur place (tuiles, glisser-déposer + flèches, largeur, fenêtre par bloc, Enregistrer / Revenir à l'origine). Le Desk manipule la DESCRIPTION des blocs : `declare()` retire les champs de lecture que le serveur refuse en écriture (`create`, `icon`, `single`, `title_field`…), `moveBlock/resizeBlock/…` sont purs, `preview()` rend l'aperçu. Habillages `workspace`, `dashboard` (`doctype` implicite dans les blocs) et `form`; les deux premiers existent en deux couches, celle de l'organisation (`scope=org`, il faut ÉCRIRE ce qu'ils montrent) et la PERSONNELLE (`scope=user`, il suffit de LIRE ; kinds `workspace_user` / `dashboard_user`, cible `<nom>@<empreinte>`), la mienne passant avant. Un espace sans fichier est un `WorkspaceDef` fabriqué qui s'habille aussi. Enregistrer ne doit jamais effacer ce que l'utilisateur ne voit pas : `overrides.keep_hidden`. `color` d'un bloc = nom de palette OU `#rrggbb` (jamais autre chose). Clés de tuile = contenu du bloc, jamais le rang (sinon une carte déplacée montre les chiffres d'une autre).
- **Paramètres = un seul onglet (`SettingsView.vue`, `/settings/:doctype?`).** Tous les réglages (DocTypes `single: true`) s'éditent ICI, par application, avec `FormView` en mode `embedded` ; `/app/<Type>/<Type>` et la « liste » d'un réglage y redirigent. Le serveur ne sert JAMAIS un réglage comme raccourci d'espace (`list_workspaces`) et un espace généré les ignore : un plugin ajoute un réglage en déclarant un DocType `single: true`, sans l'accrocher à son espace.
- **Paramètres > Général (`system_plugin_dir/`, `preferences.py`, `doc/phase-h.md`).** Le plugin `system` (YAML seul, DANS le paquet, `app/system` en dev, posé par `xcore-doctype install`) apporte le DocType unique `System Settings` (nom, logo, couleur, format de date) ; il est séparé de `xcore-doctype` parce qu'un nom à tiret ne peut ni être un `module` ni déclarer de grants. `settings_group: general` (sur un `single`) place un réglage GLOBAL dans « Général » : c'est ainsi qu'un plugin y ajoute le sien. `GET /preferences` sert à tout utilisateur identifié une liste FERMÉE de champs lus en contexte système (jamais « tout le document »). Le Desk (`stores/preferences.ts`) applique nom, logo, couleur (`lib/brand.ts` : `#rrggbb` seulement, jamais une chaîne libre dans la feuille de style) et format de date (`lib/format.ts`, réactif).
- **Collaboration (`collaboration.py`, `api/collab.py`, `doc/phase-d.md`).** Commentaires, assignations (« À faire ») et pièces jointes d'un document, tables `xdt_comment|assignment|attachment`. TOUT se juge sur le document : lire le fil = lire le document (hors périmètre `if_owner` = « introuvable »), commenter = le lire, assigner et joindre = l'ÉCRIRE, modifier un commentaire = en être l'auteur ; aucun grant nouveau. Les méthodes de `Query` n'imposent que le tenant (scénarios de fuite dans `test_query_leak.py`) : c'est le service qui lit d'abord le document avec le périmètre de l'appelant. Une pièce jointe est un fichier `xdt_file` de champ réservé `_attachment`, lu comme son document, toujours servi en téléchargement ; tout disparaît (fichiers compris) avec le document. Annuaire (`directory.py`) : xauth par défaut (`xauth.users.list.tenant` par `ctx.caller`, cache 60 s ; `allowed_callers` d'xauth doit nommer `xcore-doctype`) pour proposer, vérifier et AFFICHER (`/users`) les membres d'une organisation (l'identité est un UUID) ; sans lui, repli silencieux sur les identités observées (`Query.people`) ; ne jamais logger avec un champ `plugin` ni `msg`. Desk : `CollabPanel`/`ActivityPanel` sur la fiche, page `/tasks` (« Mes tâches », pastille dans la barre latérale).
- **Explicit context.** The service never reads ContextVars (D20). `tenant_id`/`owner` never come from payloads. HTTP routes bypass xcore's pipeline (no `PermissionEngine`, no ContextVars), so every route depends on `http_context`, also at router level.
- **Tenancy is a column** (D3). `Query._scope()` is the single choke point that adds `tenant_id`; no method takes a raw tenant. `tests/unit/test_query_leak.py` fails if a public `Query` method has no leak scenario, and also asserts the emitted SQL binds only the caller's tenant. Add a scenario when adding a method. The tenant must be covered by a principal claim (D17); `X-Tenant-ID` alone is untrusted.
- **Writes are strict, reads tolerant.** No coercion (`"12"`, `1`→bool rejected), canonical ISO dates only, **no NaN/Infinity** (a stored NaN breaks response serialization for the whole tenant). Updates replace `data` and require `version` (UPDATE … WHERE version=?; rowcount 0 → 404 or 409).
- **Portability lives in `query.py`.** JSON filters/sorts use SQLAlchemy `as_string/as_float/as_boolean`, `NULLS LAST`, `name` as tie-break. Known gap: text sort follows each backend's collation (SQLite binary vs PostgreSQL locale).
- **Async DB only** (D11). `ensure_async_database` opens a real session because `get_service("db")` may be a `TenantAwareDB` wrapper; config needs `type: sqlite+aio` (or `postgresql+aio`), plain `sqlite` is the sync adapter.
- **No module-level state** (D8). Registry, MetaData, service and router are created in `on_load` and released in `on_unload`. Don't implement `on_reload`: xcore calls it on the *old* instance before unloading, then builds a new instance and calls `on_load`.
- **Errors don't leak.** `Plugin._run` logs unexpected exceptions and returns `internal_error`; xcore would otherwise return `str(e)` (SQL and bound parameters included). Hook failures map to `hook_rejected` 422, `hook_invalid_result` 502, `hook_unavailable` 503, `hook_timeout` 504, `hook_payload_too_large` 413 (see `doc/phase1.md`).

Tests: `tests/unit` (the `db` fixture runs every DB test on SQLite and, if configured, PostgreSQL) and `tests/integration` (`boot_host` starts a real `Xcore` from the repo's `integration.yaml` in a tmp dir; read plugin routes through `host.plugin_routes()`, which uses OpenAPI because FastAPI 0.14x `app.router.routes` holds path-less `_IncludedRouter`s). `boot_host(hook_plugins=True)` also starts a trusted plugin that registers hooks and a **real sandboxed plugin** (a subprocess, ~1 s to start; the suite takes ~1 min). A sandbox worker's startup is bounded by `min(5 s, the plugin's resources.timeout_seconds)`: keep test plugins at xcore's default 10 s or activation fails under load (the harness retries the load and says so).

## xcore integration facts

- **`main.py` must call `xcore.setup(app)`**: only it installs `TenantMiddleware`; `boot()` does not. Without it `request.state.tenant_id` is never set and the plugin answers 500 `tenant_middleware_missing`.
- **Set `tenancy.isolate_db: false`.** HTTP routes never set the tenant ContextVar, so `TenantAwareDB` isolates on `default` for HTTP but on the real tenant for IPC; with existing tenant schemas HTTP and IPC diverge. `on_load` warns when it sees a `TenantAwareDB` on PostgreSQL.
- **xcore doesn't expose `tenancy.enabled` to plugins**: `doctype.enforce_tenant_binding` (default true, fail-closed) is set by hand and must be false only if xcore tenancy is off.
- **Discovery is a directory scan** (`plugins.directory: ./app`); no entry points exist yet. The host symlinks `app/xcore-doctype` → `src/xcore_doctype/plugin_dir` (plugin.yaml + shim `src/main.py`). The shipped wheel contains that folder but xcore won't discover it. `strict_trusted: true` blocks the unsigned plugin; the dev config sets it to false.
- **Manifest** (`plugin_dir/plugin.yaml`): `permissions` (`doc.*`, `meta.*` → `execute`; absent means `deny_all`), `allowed_callers: ["*"]`, and the `doctype:` block read through `self.ctx.config["doctype"]`. Per-deployment settings live in the operator's installed copy of that manifest (`xcore-doctype install` never overwrites it without `--force`); `doctypes_dirs` is relative to the launch directory.
- **Auth = xauth (`app/auth`, copied from orchestra-backend and adapted: `doc/xauth.md`).** `decode_token` returns `AuthPayload(sub, roles=[names], permissions=[grants of the tenant], user={email, tenant_id})`; `sub` and the `tenant_id` claim are UUIDs. Grants are announced with `rbac.declare` (first segment must be the declaring plugin's name, `[a-z0-9_]+`; reserved: admin rbac auth tenants user license plugins); xauth gives them to its `admin` role as they arrive, so **xauth must load BEFORE the plugins that declare** (they `requires: [..., auth]`; an event emitted before xauth listens is lost). xcore-doctype only *checks* grants and logs the ones its DocTypes cite (`xcore-doctype loaded`, field `grants`). `cross_tenant_grant` is looked up in `permissions` only (`admin:*` is xauth's platform admin; the default is unchanged). xcore only expands `${VAR}` in a manifest `env:` block when the variable EXISTS (no default syntax; a missing one rejects the plugin).
- **Login = identifier (username OR e-mail).** The Desk's login field is plain text; `session.login(identifier, …)` sends `{username}` or `{email}` by the presence of `@`, xauth's `LoginRequest.identifier` resolves it (`UserRepository.get_by_identifier`: e-mail compared case-insensitively, username lowercase). A username is 3-32 chars `[a-z0-9._-]`, never contains `@` (so no ambiguity), unique (`xauth_users.username` + index `ux_xauth_users_username`), chosen at registration (optional) or in Mon compte (`PATCH /account/username`: password + OTP when MFA is on); the seeded admin gets `ADMIN_USERNAME` or the local part of their address. An existing xauth database gains the column at startup (`app/auth/src/utils/db_upgrade.py`, additive and idempotent: extend `ADDED_COLUMNS` for the next one). xauth's own rate limit (5 logins / 3 registrations per minute per IP, in code) applies to scripts and tests too. `doc/xauth.md` § "Se connecter".
- **Virtual DocTypes, `iam`, profile (`doc/iam.md`).** A DocType with `source: <name>` keeps its documents in a source registered by its plugin (`doctype_sources`, `sources.py`): the engine still applies grants, strict schema, `read_only`, links, filters/sort/search/aggregates IN MEMORY (`memory.py`, parity-tested against the SQL path in `tests/unit/test_virtual_doctypes.py` — change one interpreter and that fails), a missing source is a 503, a crashing one a 502 without detail. No history/hooks/series/files/submit for them (`schema._source_rules`). `app/iam` (module `iam`, requires `auth`) exposes xauth as DocTypes `Permission` (read-only catalogue), `Role`, `Member` through `app/iam/src/source.py` → IPC `xauth.iam.*` (`app/auth/src/{services/iam.py,ipc_iam.py}`; callers named in xauth's `allowed_callers`: `xcore-doctype`, `iam`, `hr`): the engine authorises, **xauth re-judges the actor** (organisation owner or platform admin writes; a plain member reads the directory only). `rbac.declare` grants may carry `default_roles` (the iam grants also go to `tenant_admin`). `User Profile` uses `naming: owner` (one document named like the user) and the special grant `@authenticated` (any identified user, never declared to auth). `hr` requires `iam`: `Employee.user` links a `Member`, hook `hr.employee_access` (app/hr/src/access.py) closes the account when the status becomes « Parti » (refuses the save if the actor cannot). Desk: `FieldMeta.read_only`, `DocTypeMeta.virtual`, « Mon profil » (`stores/profile.ts`, `ProfileView`), Settings rail links to the Member/Role/Permission lists when readable. xauth's rate limit is now the manifest's `rate_limit:` block (`RateLimitPolicy`: `enabled: false` in tests).
- **Mail and the Desk's Settings > Système.** xauth's mail goes through the `ext.email` extension (`extensions/xmailler`, copied from donna, `services.extensions.email` in `integration.yaml`; no SMTP host = **simulated mode**: status stays READY, messages are logged and counted, never sent; `XAUTH_SMTP_*` in `.env` configures it). `app/auth/src/routes/mail.py` (`/mail/status`, `/mail/test`) is platform-admin only and never returns a secret. With xauth as login (`services.auth`, root derived from `login_url`) the Desk's Settings gets a "Système" group (`/settings/~account|organisation|users|roles|permissions|accounts|mail|audit|api`, `ui/src/components/admin/`, client `ui/src/lib/xauth.ts` = `XauthClient extends ApiClient`, `HttpMethod` includes `PATCH`) covering what a screen can do with xauth (table and the deliberate exclusions in `doc/xauth.md`): xauth decides each right, a 403 is shown as "réservé", never as a failure. **xauth's JWT carries NO permissions**: `session.loadPermissions()` reads `/rbac/me/permissions` and `session.platformAdmin` (`admin:*`) only hides the platform-only rubriques (`permissions`, `accounts`, `mail`); never use it as a right. The bell (`NotificationsMenu`, `stores/notifications.ts`) shows xauth notifications: text is HTML-escaped by the server (decode to display, never `v-html`) and a link is followed only if it is `#/…` or https (`safeTarget`). A global role's permissions are added/removed by permission ID, an organisation role's by NAME (xauth's own asymmetry). `ui/e2e/look-admin.mjs` walks the pages and the bell in a real browser.
- **The Desk's auth screens (`ui/src/views/`, all `meta.public`, contracts in `doc/xauth.md` § "Desk : la connexion").** `session.ts` also drives `POST …/register` (a account without an organisation), `…/password/forgot|reset`, `…/invites/token/{token}` (read WITHOUT a session) + `…/invites/accept` (with it), `GET …/oauth/providers` + `…/oauth/{p}/authorize` (nonce `app_state` kept in sessionStorage, returned on `#/oauth` by `OAuthCallbackView`), `GET …/tenants/` and `POST …/select-tenant` for the organisation switcher in `AppShell` (reload: Desk caches are per organisation). **Emails link to the DESK as a web URL** (`desk_url` = `app.desk_url`/`XAUTH_DESK_URL`/`<base_url>/app/xcore-doctype/desk/`, read in `app/auth/src/main.py`, used by the password/invite senders and the register reply): no `erp://` deep-link anywhere except xauth's default OAuth redirect target, which an operator enables with `OAUTH_WEB_REDIRECT_ORIGINS`.
- **Test auth:** the engine's tests do not start xauth: `tests/support/dev-auth/` is a TEST-ONLY HMAC token backend (named `auth`, so the repo's plugins `requires` it; `tests.support.mint_token` forges any principal; `boot_host(auth_members=…)` imitates the user directory). `tests/integration/test_xauth_real.py` boots the REAL `app/auth` (`boot_host(xauth=True)`: throwaway JWT keys, administrator from the environment) and logs in through `/app/auth/login`. `integration.yaml` also contains development `secret_key`/`server_key`; `app.secret_key` is the `X-Plugin-Key` for every `…/ipc/…` route including lifecycle control.
- **Sandboxed plugins can't call others** (`call_plugin` is unavailable to them), `EventBus.emit` swallows handler errors and can't veto: this is why `validate`/`before_save` are direct calls and only `after_*` will be events (phase 1).
- **A plugin whose `plugin.yaml` is not valid YAML is skipped with only a WARNING** (`invalid manifest`), so its hooks silently never register and every save of a DocType citing them answers 503 `hook_unavailable`. Quote any `description:` containing `: `.
- Logging: `xcore.kernel.observability.get_logger` with kwargs, not `logging`. `cron`, `interval`, `on_event`, `cached`… exist only with the optional `xcdk` package.
- `plugin_prefix` is `/app` in this repo's `integration.yaml` (xcore's default is `/plugin`); read it from config, don't hard-code it.
